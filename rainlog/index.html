three releases · one data file

Rain Log

A rain gauge in the yard knows more than the weather app does. Rain Log keeps a calendar of your daily readings in one small JSON file and turns it into rolling totals you can actually use: the last 24 hours, the week, the month, the season, the year. Every release does the same job on a different surface, and they all agree on the file.

01Omarchy Rain Log — the plugin

The bar widget

Omarchy 4.x · github.com/captain-reginald/omarchy-rain-log

Rain Log lives in the Omarchy bar as a raindrop. Click it for the card: today's gauge reading in tenths of an inch, rolling totals for 24 hours, 72 hours, the week, the month and the season, a custom window (14 days by default), and your last five rainy days. Every total can be scrolled backwards with the arrows, so this week can be compared against last week without losing today.

Units match the markings on a US rain gauge: 23 means 2.3 inches. Entering 0, or clearing the field, removes that day. Seasons are meteorological (Dec–Feb, Mar–May, Jun–Aug, Sep–Nov).

Install

# requires Omarchy 4.x with omarchy-shell
omarchy plugin add https://github.com/captain-reginald/omarchy-rain-log --enable

# without --enable, or to pick where it sits on the bar
omarchy plugin enable io.github.captain-reginald.rainlog

# later, to pull the newest version
omarchy plugin update io.github.captain-reginald.rainlog
  • Bar shows a plain raindrop by default; a count can be enabled and set to daily, weekly, monthly, seasonal or yearly.
  • Calendar editor for filling in missed days or fixing a typo.
  • Custom range window (14 days by default) for any time frame you care about.
  • Follows the active Omarchy theme: colors, typography, spacing, corner radius.
  • No background service; the shell reads the JSON file directly.

02Rain Log Server — the web app

The big screen and the phone

v1.0.0 · github.com/captain-reginald/rainlog-server · releases

A small, self-hosted web companion that reads and writes the same rainlog.json, so a synced folder gives you the bar widget on the desktop and this app on everything else. No database, no accounts, no telemetry — one JSON file, a few flat companion files, one container on port 8080.

git clone https://github.com/captain-reginald/rainlog-server.git
cd rainlog-server
docker compose up -d
# then open http://<host-ip>:8080

Prefer a prebuilt image? ghcr.io/captain-reginald/rainlog-server:latest, or pin :v1.0.0 / :1.0 / :main. Multi-arch: linux/amd64 and linux/arm64. The compose file defaults to PUID=1000/PGID=1000 and America/Denver; set your own timezone and IDs before starting.

  • Rolling totals for the month, the season, the year, and one to three configurable windows of any length (up to 365 days) — each with back/forward stepping.
  • Local climate comparison: enter your locality and see where you stand against the 1991–2020 30-year normals, month by month.
  • Calendar editing for catching up or fixing a typo.
  • Charts: monthly totals, recorded vs. average by month, every year on record.
  • CSV and JSON import/export with a dry-run preview before anything is written.
  • Automatic snapshots in .rainlog-backups/; import/export; PWA shell for a home-screen icon.
  • Optional millimetre display — storage stays in tenths of an inch.

Repo: captain-reginald/rainlog-server · image: ghcr.io/captain-reginald/rainlog-server · GPL-3.0

03Rain Log Desktop — the app

The card, as a window

v1.0.0 · github.com/captain-reginald/rainlog-desktop · releases

The same card the plugin opens, packaged as an ordinary application. It exists for desktops that aren't Hyprland, and for Windows. Frameless window, slim drag strip with minimize/close, no tray icon, no background process — closing saves and quits.

On Linux it follows the Omarchy theme when one is present (colors, typography, spacing, corner radius) and falls back to a bundled palette otherwise; on Windows it uses the bundled palette. It adopts the plugin's configured data path on first run, so there is no migration step.

Download the latest release: Rain Log Desktop v1.0.0.

  • Linux — RainLog-v1.0.0-linux-x86_64.AppImage, self-contained, no install required. A .sha256 is published alongside it.
  • Windows 10 x64 — RainLog-v1.0.0-windows-x64.exe, NSIS installer; administrator approval required. Bundles the Visual C++ runtime and creates Start Menu and public Desktop shortcuts. A .sha256 is published alongside it.
# optional: install the AppImage into the application menu
chmod +x RainLog-v1.0.0-linux-x86_64.AppImage
./RainLog-v1.0.0-linux-x86_64.AppImage --install

# and later, remove it
~/Applications/RainLog-Desktop.AppImage --uninstall

On Hyprland, windows tile by default. If you want Rain Log Desktop to float like the plugin card:

# ~/.config/hypr/hyprland.lua
hl.window_rule({ name = "rainlog-desktop", match = { class = "rainlog-desktop" }, float = true })

Repo: captain-reginald/rainlog-desktop · GPL-3.0

04How they fit together

  1. The plugin (or the desktop app) is the writer. You enter the gauge reading; the file is rewritten atomically with two-space JSON and sorted keys, so sync diffs stay small.
  2. Point the data file path at a folder your sync tool already carries — Syncthing, Resilio, a git repo, anything file-based. The plugin creates rainlog.json on first run if it's missing.
  3. The server, pointed at the same folder, re-reads the file every five seconds and re-reads before each write, merging only the days you touched. A snapshot is taken if the file changed underneath it.
  4. None of the three requires the others. Use the plugin alone on one machine; use the server alone on a NAS; use the desktop app on a Windows laptop and sync everything.

Concurrent editing from two devices at once is best avoided — sync first, then edit. The server narrows the window but can't remove it. Web-only preferences live in rainlog-web.json next to the data file and are never written into rainlog.json.

05The data file

Everything revolves around one file. The default path is ~/Documents/rainlog/rainlog.json — the plugin's setting wins if it disagrees, and the desktop app adopts the plugin's configured path on first run.

{
  "entries": {
    "2026-11-14": 23,
    "2026-11-15": 12
  }
}
  • Values are whole tenths of an inch, keyed by local calendar date (YYYY-MM-DD).
  • A missing key means no rain that day. Entering 0 deletes the entry — there is no zero rain measurement, only "didn't rain".
  • Date keys are validated as real days; values must be integers from 1 to 9999.
  • Two-space JSON, sorted keys, no trailing newline — small diffs, friendlier syncing.
  • The server preserves unknown top-level keys it doesn't understand; it will also refuse to write if the file is corrupt rather than replace it.
